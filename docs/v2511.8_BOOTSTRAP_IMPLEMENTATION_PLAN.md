Per-file research-grounded plan to implement user-triggered "sync from bootstrap"
across CLI, RPC, and GUI surfaces. Builds on v2511.7's static
`freycoin-bootstrap-v2511.7-h13819.tar.gz` release asset.

Branch: target `v2511.8-bootstrap` off `origin/main` (currently `305c92636b`).
Version: `CMakeLists.txt` `CLIENT_VERSION_REVISION 7` → **8**.

## Research summary (file:line refs from /mnt/d/AI/Freycoin-r8)

### Init / startup ordering — clean splice point exists

- `-loadblock` parsing: `src/init.cpp:512`. Ingestion: `src/init.cpp:2353-2360` (background thread post-AppInitMain).
- AppInit phases:
  - `AppInitBasicSetup` (866-901) — signal handlers, networking
  - `AppInitParameterInteraction` (903-1018) — flag combination validation
  - `AppInitSanityChecks` (1231-1253) — kernel checks; **calls `DataDirPreflight()` at 1247** before `LockDirectories`
  - `AppInitLockDirectories` (1255-1265)
  - `AppInitInterfaces` (1267-1272)
  - `AppInitMain` (1804+) — logging, scheduler, wallet, network, **`InitAndLoadChainstate` at 2190**
- **Bootstrap splice point**: between `init.cpp:2181-2190`, BEFORE `InitAndLoadChainstate`. The window is: network interfaces created (1937), peerman not yet (2231), chainstate not yet opened.
- Existing `-reindex` pattern (init.cpp:2186, options at 1448) sets `wipe_chainstate_db` so LoadChainstate creates fresh DBs. Bootstrap can use the same flag-then-reinit pattern.
- `DataDirPreflight()` at `src/init.cpp:1129-1210` is our v2511.7 hook — extend to detect `.bootstrap-marker` and resume/rollback on next start.

### HTTPS — current build cannot do it natively

- `depends/packages/libevent.mk` builds with `-DEVENT__DISABLE_OPENSSL=ON` → libevent has **no TLS support**.
- `src/freycoin-cli.cpp` uses libevent's HTTP client (RAII wrappers in `src/support/events.h`) but only over plain HTTP for localhost RPC.
- No libcurl, no boost::beast, no OpenSSL/mbedtls in `depends/packages/`.
- `Qt6::Network` IS linked (`src/qt/CMakeLists.txt:222`) but **unused anywhere** in `src/qt/`.
- **Decision (cross-platform shell-out)**: use `curl` for daemon downloads, `QNetworkAccessManager` for GUI. Both ubiquitous since 2018 (curl ships with Windows 10 1803+, all Linux distros, macOS). Trade-off: 30 LOC of subprocess wrapping vs 2000+ LOC pulling OpenSSL through libevent rebuild. Sentry: shell-out goes through a single `RunCurlDownload(url, dest, expected_sha256)` helper that validates URL scheme is `https://`, refuses arguments containing shell metacharacters, uses `execve`-style argv list (not shell string concatenation).

### Tar extraction — same shell-out logic

- No tar reader anywhere in tree/depends. `libarchive` would be a substantial new dep.
- Windows 10 1803+ ships `tar.exe` (bsdtar). Linux/Mac universal.
- **Decision**: shell-out to `tar` with explicit path-allowlist enforcement BEFORE extraction. We list tarball contents with `tar tzf`, validate every entry against the allowlist (`blocks/*`, `chainstate/*`, `indexes/*`, no `..`, no absolute paths, no symlinks), then extract with `--no-same-owner --no-same-permissions`.

### SHA256 + fs safety — all primitives present

## Decisions

| Decision | Choice | Rationale |
|---|---|---|
| HTTP transport (daemon) | shell-out to `curl` | 30 LOC vs 2000 to add OpenSSL. Curl is universal since 2018. |
| HTTP transport (GUI) | `QNetworkAccessManager` | Qt6::Network already linked. Native progress signals. |
| Tar extraction | shell-out to `tar` with pre-list allowlist | bsdtar shipped on Win10 1803+, universal otherwise. Cleaner than vendoring libarchive (~50K LOC). |
| Bootstrap timing | Run BEFORE `InitAndLoadChainstate` (init.cpp:2190) | Existing chainstate is renamed-out before LevelDB opens. No teardown of running DB needed for the CLI path. |
| Running-daemon RPC path | Stop-and-restart via systemd sentinel? **No** — RPC refuses if any wallet loaded; otherwise calls `ChainstateManager::ResetChainstates()`, swaps dirs, re-inits chainstate in-place. Heavier code path, gated by `-allowlivebootstrap=1`. | First version: CLI flag only, RPC method but only if no wallet loaded, GUI shows a "restart needed" dialog instead of in-place. Defer in-place to v2511.9. |
| Manifest distribution | Hardcoded list in `chainparams.cpp` per release | Same trust model as `assumevalid`. List grows; old entries stay valid. |
| Backup retention | Keep `<datadir>/.bootstrap-backup/<timestamp>/` indefinitely; daemon warns after 30 days | Operator decides when to delete. |

## Marker file format

`<datadir>/.bootstrap-marker.json`:

```json
{
  "version": 1,
  "phase": "downloading" | "downloaded" | "extracting" | "swapped" | "complete",
  "started_unix_ts": 1746305000,
  "url": "https://...",
  "expected_sha256": "eb825dd...",
  "actual_sha256_partial": "...",
  "bytes_downloaded": 1234567,
  "bytes_total": 7000000,
  "backup_path": "<datadir>/.bootstrap-backup/2026-05-04-1503",
  "old_chainstate_height": 13479,
  "snapshot_height": 13819
}
```

`BootstrapPreflight()` reads this on startup. Phase transitions:

- `downloading` → resume via curl `--continue-at <bytes_downloaded>`
- `downloaded` → re-verify SHA256, proceed to extract
- `extracting` → roll back: `rm -rf` partial chainstate, restore from `backup_path`
- `swapped` → done; daemon proceeds normally; marker is moved to `<datadir>/.bootstrap-history/<timestamp>.json`
- `complete` → marker is just informational; daemon ignores

## Trust model + safety enforcement (concrete)

1. **URL validation**: `https://` only. No `http://`, no `file://`, no `ftp://`. Refuse before invoking curl.
2. **No shell injection**: curl invoked via `argv[]` array (no `system()`, no string concat). Same for tar.
3. **Bandwidth/disk preflight**: refuse if `tarball_size_bytes` × 3 > `df --output=avail <datadir>`.
4. **Tar entry allowlist**: enforce regex `^(blocks|chainstate|indexes)/[^/]+(/[^/]+)*$` (no `..`, no `./`, no leading `/`, no symlink entries). Run `tar tzf` first, fail if ANY entry doesn't match. Then `tar xzf` to a staging dir, then `mv` over.
5. **No-symlinks**: `tar --no-same-owner --no-same-permissions` plus a manual loop to reject any entry of type `symlink`/`hardlink`.
6. **Hash verification**: stream CSHA256 over the downloaded file. Compare to manifest entry. ABORT before any extract if mismatch.
7. **Atomic swap**: rename existing `blocks/` → `<backup>/blocks_old`, etc. Then `mv` extracted dirs into place. If any rename fails, unwind in reverse.
8. **Wallet refusal (RPC path)**: `if (!GetWallets(*node.wallet_loader->context()).empty()) throw "close all wallets first"` before doing anything destructive.
9. **Datadir lock semantics**: CLI path runs before lock; RPC path holds it throughout (only chainstate dirs swap, lock file untouched).

## Out of scope for v2511.8

- **In-place RPC swap on running daemon with loaded wallet**: not for first version. Operator must close wallets, run RPC, daemon stops, swaps, restarts. Defer the seamless live path to v2511.9 once the engine is hardened.
- **P2P snapshot exchange**: out of scope per round-2 proposal. Adds protocol surface we shouldn't take on.
- **Bittorrent / IPFS distribution**: out of scope. Stick to GitHub releases with hash pinning.
- **Auto-trigger on stuck-sync detection**: out of scope. Operator-triggered only.

## Version + release path

- v2511.8 cuts the engine + CLI flag + RPC method + GUI dialog.
- v2511.8 release notes call out `-syncfrombootstrap` and Tools→Resync as the recommended onboarding path.
- v2511.8 bootstrap tarball goes up as the second manifest entry alongside v2511.7's.
- v2511.9 candidate: in-place live swap with wallet-aware locking; manifest pruning policy (keep last 6 entries).

## Open decisions for human

2. **GUI Tools menu placement**: after Settings or after Window? Bitcoin Core's debug console menu would have been here if they had one. I'd put it after Settings.
3. **Backup retention default**: keep forever, prompt-to-delete after 30 days, auto-delete after 90 days? Recommendation: keep forever, log warning after 30 days, never auto-delete.
4. **Manifest size cap**: do we keep ALL bootstrap entries forever or prune? Recommendation: keep last 6 entries (covers ~6 releases of operators stuck on older binaries).
